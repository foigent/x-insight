# Connection synchronization (FPV20 / schema46)

On **Connectors**, each UR installation has an Auto sync preference and a local status view. New connections start in manual mode. Upgrade preserves existing Auto preferences and existing worker intervals. To quiet a test connection, identify that exact installation and explicitly switch its Auto sync off; upgrading does not pause every connection.

Auto sync controls XI outgoing Feed, source facts/events, current runtime, content, budgets and enrollment/capability maintenance for that connection. Saving a new interval accepts whole seconds from 5 through 3600; newly enabled connections default to 60 seconds. It is a minimum polling interval: original retry backoff and controller maintenance may take longer. Existing configured intervals remain in effect until a new interval is saved. Opening or refreshing a status page does not trigger a UR fetch. Local retention, expiry, audit and historical reading continue.

**Sync once** requires Auto sync off. It advances the applicable categories fairly and stops each category at its observed boundary. The whole run is bounded by 60 seconds, 32 data/control pages and 64 application HTTP attempts, including capability requests and failed attempts. It never enables Auto sync or resumes automatically after restart. Empty, completed, partial, error, cancelled, expired and interrupted outcomes have different meanings. A partial outcome is not proof of complete source coverage. A new attempt is an explicit new action. A lost response retains the original request locally; confirm that same request or refresh local status before starting another.

**Stop sync** changes the durable revision first. Already admitted work can remain in flight. The effective state stays stopping or unknown until the relevant worker completion is known. A timeout or missing worker heartbeat does not establish quiet. Results from a superseded revision cannot advance a database cursor or publish new collection state. Evidence committed before the stop remains retained and can be safely deduplicated when collection resumes.

The original Connect consent has a single bounded initialization continuation; it does not set Auto sync. A replayed ACK cannot renew it. If either product's bounded setup run completes before the other product is ready, the connection remains pending rather than being reported complete. Resume the required local action explicitly. XI can resume its own outgoing synchronization from its UI or CLI while its listener remains available. UR must resume its own control polling from its local UI or CLI. XI's quiet state is not evidence of UR quiet, and no cross-admin credentials or hidden remote wake are introduced.

Pause does not revoke authorization, clear a requires-attention condition or reset a cursor. If source retention expires, the gap remains visible and the existing explicit recovery procedure still applies. Last outgoing check and last data commit are shown separately; neither guarantees full source coverage.

An explicit delegated policy save uses its existing human account and immutable operation reference for a separate bounded control call (60 seconds / 32 pages / 64 attempts). It leaves Auto off and grants no collection worker permission. An unconfirmed result can be read within that original remaining budget; replay does not extend it. A terminal result is read locally. After the budget expires, use an explicit Sync once for remote recovery, retaining the original policy operation reference. Live policy discovery/read pages also require Auto or Sync once; opening those pages does not grant an implicit control run. Credential recovery keeps its existing human confirmation ticket and inbound protocol. At most 32 finite receipts are retained; a failed policy preflight receipt cannot be evicted until the original durable policy operation protects its identity. If that bound cannot be maintained, a new run fails closed.

The local administrator can use `xinsightctl connector-sync status|auto-off|auto-on|once --installation-id ID --actor SUBJECT`. Use the exact ID and an existing authorized local account subject. Changes require the observed `--expected-revision` and a stable UUID `--request-id`; Auto-on may specify `--cadence-seconds`. A retry reuses the original body and UUID. Do not start another task while the previous outcome is unconfirmed.

This candidate has a new schema and artifact identity. Local tests do not establish CI, signed distribution, installation or Target acceptance. Frozen FPV19 artifacts and signing inputs retain their original identities.
