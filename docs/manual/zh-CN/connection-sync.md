# 连接同步（FPV20 / schema46）

在“连接器”中，每条 UR 连接都有持久化的自动同步偏好和本地状态。新连接默认手动；升级保留既有连接的自动行为及配置间隔。安静测试时，需要核对准确连接并显式关闭，不会因升级而暂停所有连接。

开关覆盖 XI 发出的 Feed、来源事实／事件、当前运行状态、正文、预算和 enrollment／capabilities 维护请求。保存间隔接受 5 至 3600 秒的整数，新开启时默认为 60 秒；这是最小轮询间隔，原有退避和维护周期可能更长。未保存新间隔时继续使用既有配置。打开或刷新状态页面不触发 UR 采集；本地保留期、到期清理、审计和历史阅读继续运行。

“同步一次”要求关闭自动同步。各适用类别轮转推进，到达本次可观察边界后停止该类别；整次任务最多 60 秒、32 个数据／控制页、64 次应用级 HTTP 尝试，capabilities 与失败尝试也计数。单次任务不会开启自动同步，不会在重启后自动重放。空结果、完成、部分完成、错误、取消、到期和中断分别记录；部分完成不代表覆盖完整。响应丢失后保留原请求 ID 和正文，先确认同一请求或刷新本地状态，再开始新任务。

“停止同步”先持久化新版本。已获准的请求可能仍在结束，界面会显示“正在停止”或“未确认”；超时、失联本身不能证明静默。旧版本结果不能前移数据库游标或发布新的采集配置；停止之前已提交的证据继续保留，恢复后沿用原有去重。

最初的 Connect 同意只带一次有界初始化机会，不会开启自动同步，重放 ACK 也不会续期。若某端的有界初始化先于另一端就绪而结束，连接仍显示待完成，需要显式恢复本地动作。XI 从自己的界面或 CLI 恢复出站，UR 从自己的本地入口恢复反向控制轮询；listener 保持可用。XI 本地静默不能证明 UR 静默，不增加跨管理员凭据或隐藏唤醒请求。

暂停不会撤销授权、清除需要处理的错误或重置游标。源端保留期到期后，缺口仍然保留，继续使用既有显式恢复流程。“最近出站检查”和“最近数据提交”分别显示，不能据此推定已覆盖全部来源数据。

显式保存 UR 委托策略时，使用原人类账户和不可变操作标识，单独获得最多 60 秒／32 页／64 次尝试的控制通信授权；Auto 仍关闭，采集 worker 不获准运行。未确认的结果只能使用原任务剩余预算回读，重放不续期；终态结果直接在本地读取。预算到期后，显式启动“同步一次”进行远端恢复，保留原策略操作标识。实时策略发现／读取页面也需要 Auto 或“同步一次”，打开页面本身不产生控制任务。凭据恢复继续使用原有人类确认票据及入站协议。有限回执最多保留 32 份；策略预检失败的标识在原生持久操作记录能够防止重建之前不会被淘汰，无法保持上界时拒绝新增任务。

本地管理员可用 `xinsightctl connector-sync status|auto-off|auto-on|once --installation-id ID --actor SUBJECT`。必须使用准确 ID 和已有、获准的本地账户 subject；变更另带状态回读的 `--expected-revision` 和固定 UUID `--request-id`，开启时可指定 `--cadence-seconds`。重试沿用原 ID／正文，未确认前不另建任务。

FPV20 使用新的 schema 和制品身份。本地通过不代替 CI、签名分发、安装及 Target 验收；冻结的 FPV19 制品和签包材料保持原身份。
