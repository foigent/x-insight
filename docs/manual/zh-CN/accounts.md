# 账号与项目阅读

本章描述 FPV25/schema47 源码候选。本地通过不等于制品发布或真实安装验收。

## 首个 owner 与已有安装

原生安装器只初始化一次数据库账号权威。升级时，合法的 v1/v2/v3 旧账号文件原子导入，保留稳定 subject、用户名、角色、停用状态和密码摘要。保留私有原件供历史恢复。初始化后，运行产品仅使用数据库；修改或恢复旧文件不能重置当前密码或身份。数据库不可用时拒绝认证。

没有导入账号的新安装不设默认密码。完成安装与批准的 HTTPS 配置后，获授权的主机管理员使用已验证控制器生成首个 owner 的私有激活交付。先在选定位置建立0700私有目录，输出须为该目录中尚不存在的精确文件。

```text
sudo /opt/x-insight/current/bin/xinsightctl access bootstrap-owner --username owner --output /approved/private/owner-activation.html --check
sudo /opt/x-insight/current/bin/xinsightctl access bootstrap-owner --username owner --output /approved/private/owner-activation.html
```

check 只读，不创建账号或链接。实际操作写入0600私有 HTML 交付文件，链接只指向该安装配置的 HTTPS origin。安全交给本人；本人打开链接，自行设置并确认至少12字符的密码，再正常登录。链接15分钟过期、只能用一次。浏览器移除地址中的凭据，不保存到浏览器存储。不要把链接放入聊天、issue、日志或共享文档；过期后文件仍按私有资料保管。文件写入或提交失败时，先核对精确账号和已保留文件，再决定下一步。

已有管理员身份时不能再次创建首个 owner。owner 无法正常登录时，获授权主机管理员可用 `access directory` 核对，再运行 `access recover-account --subject EXACT_SUBJECT --expected-revision CURRENT_REVISION --output /approved/private/new-handoff.html --check`，核对后使用同一命令去掉 `--check`。这是明确的应急路径，保留 subject 与 grant，拒绝恢复已停用账号，不要求管理员知道本人密码。不要直接改表或旧账号文件。

## 日常账号操作

owner 登录后打开**账号**（`/access/accounts`）。**邀请新账号**只用于尚不存在的用户名：先预览邀请，再在确认区核对目标账号和动作，输入自己的当前密码确认。恢复已有 reader 时，应在**现有账号**的精确行选择**创建恢复链接**，核对目标后再确认；它与邀请新账号、确认项目阅读授权是三个不同动作。激活／恢复链接只交给对应本人，由本人设置密码。恢复立即阻止目标账号旧密码和旧会话；完成改密、停用／启用只推进该账号的认证版本，不让其他人掉线，不重启服务。仍待激活的账号启用后仍须激活。普通账号页面不能停用、降级或恢复 owner，也不改用户名或稳定 subject。

成功后的结果明确显示目标账号和激活／恢复链接。**待本人设置密码**表示链接已签发，不表示本人已经完成设密。本人仅打开一次完整链接，自行输入并确认新密码；完成页会说明更新了哪个账号。设置密码不会自动以该账号登录；浏览器仍登录其他账号时，使用明确的退出并登录操作，再在正常登录表单输入密码，用户名取自服务器核实的目标。登录后的页面显示真实当前账号和角色。

若修改已成功但列表刷新失败，应保留结果，仅刷新状态，不重复修改。若提交结果不确定，页面先阻止再次写入并要求核对状态。设密结果不确定时不重复使用一次性链接，可核对当前会话或尝试正常登录；不能仅因没有确认画面就认定失败、反复生成链接。

正常入口根据当前阅读范围选择：仅有元数据权限的账号直接进入 Runtime，不探测无权读取的经济汇总或资源活动。局部面板拒绝不会令整个账号掉线；真实过期、撤权或账号变化仍立即关闭受保护数据并重新核对会话。正文不可用提示不能证明来源已捕获正文，也不能证明当前账号有正文读取权。

## owner 阅读须明确授权

管理能力不默认授予来源数据。在**项目阅读**中明确选择账号、已注册来源、精确项目和元数据字段，预览并核对后用当前密码确认。页面不复制 reader 的 grant；不创建通配、正文、用途、资源或预算授权，也不覆盖高级 grant。高级范围继续沿用已有原生审阅路径。

同一 owner 可管理产品并阅读明确获权的项目，无须日常切换账号。未获权项目与其他项目继续拒绝。明细／覆盖与上下文、身份、成本、运行、尝试、能力、策略、去向等元数据，不等于正文读取权；本页面始终不开放正文。已有 grant 取并集，窄授权不限制其他宽授权，撤销只影响该条。普通 reader 仍用于最小权限验收。

## 备份与恢复

使用完整私有原生备份。schema47 私有备份使用 v2 manifest，通过服务端摘要绑定账号权威、凭据／版本与激活票据，回执不包含凭据值。恢复保留这些行、稳定 subject、已有 grant 和审计历史。服务激活前，以精确恢复操作记录退役所有恢复前的激活／恢复链接，旧快照不能让已使用链接重新有效；需要时再生成新恢复链接。数据库提交完成、阶段日志尚未写入时的中断可接续，但不能据此忽略其他权威状态漂移。

对于早于账号权威的业务备份，原生恢复将当前已初始化的数据库账号保留到空的前向迁移目标中，不从过时主机文件恢复当前凭据；业务 grant 和事实仍取所选备份。真正早于 schema47 的安装仅从合法旧文件初始化一次。执行前区分这些前态，原库与新库按现有批准的退役流程保留。
