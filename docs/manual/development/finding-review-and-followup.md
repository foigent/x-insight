# Finding 复核与跟进：开发候选使用说明

本说明对应当前 schema28 开发候选，不表示正式 0.3.0-rc.13/schema23 已包含这些能力。正式手册及发布身份仍按其原版本维护；本地候选通过也不等于已发布。

## 账号与只读访问

`xinsight.local-accounts.v1` 继续兼容。开发候选的 `xinsight.local-accounts.v2` 支持 `workbench_reader` 与 `investigation_reader`，严格 schema 为 `schemas/access/local-accounts-v2.schema.json`。`investigation_reader` 可读 Case、依据、历史和封存包，不能创建、引用、修改、封存 Case 或管理连接；有 Case 读取权限的人类角色新增 `investigation.preferences.write`，仅用于保存自己的队列筛选。`workbench_reader` 不能读取 Case 或调查证据。更改账号 schema 不会自动改变原账号角色；真实账号配置仍需单独授权。

## 人工复核与跟进

从执行调查中选择证据节点或缺口，展开“从所选依据开始复核”；也可在 Case 页面从已有引用开始。
明确勾选本次采用的 Evidence/Gap，填写 Finding 的判断陈述，选择已有开放 Case 或填写新 Case。
预览会显示实际采用的证据身份、缺口解决版本及说明。确认后，Case（如新建）、Finding、引用、
初始复核、明确“未开始”进度与创建回执一次保存；“待复核”不会把判断确认为事实，责任仍未记录。
旧的单独创建入口继续保留，旧记录不会自动补成“已复核”或“未开始”。

在 Finding 的“复核与跟进”中，结论、责任与进度分别记录。证据支持须选择支持引用；证据不支持须有
反证；证据不足须有缺口或明确缺少什么。登记责任不会授予账户权限，也不会自动开始跟进。
未结束的 Finding 超过责任期限时显示跟进逾期；尚无进度的记录同样计算逾期，同时保留“进度未记录”的说明。

结束跟进需要原因及以下一种依据；复核结论不会随进度变化：

- 已验证修复：人工核验说明、覆盖范围、时间和采用的修复后核验引用；不代表 XI 执行了修复。
- 经复核排除：当前采用依据下的“不支持”结论和反证。依据变化后先重新复核。
- 重复并入：核对另一 Case/Finding 的准确 ID、陈述及同一判断的理由；拒绝自身和循环，不删除原记录。
- 仅结束本次跟进：说明结束原因及剩余未知，不表示风险消除或风险接受。

开放 Case 中的已结束 Finding 可以说明原因后重新跟进。后来增加的相关引用、已采用 Gap 的解决
内容变化会在读取时提示重新评估，并标明评估时间；已知但未选用的引用不被误标成新证据。提示不会
覆盖历史结论或自动重开。展开依据可分别读到“当时采用”与“当前”内容；引用不可读会单独提示。
复核、进度与责任历史按 Case 版本组合展示，各自分页并固定读取上界。

网络结果未知时，本标签页保留原命令；刷新后使用“原样重试”，不要另建一套。确认回执后页面重新
读取当前记录，旧回执不冒充最新状态。版本冲突需要重新读取、核对并预览。权限失效时先恢复合法
会话，未确认的原命令不会因离开页面而变成已成功。

新封存包使用 v3，包含复核/进度、当时实际采用的 Gap 内容、责任历史及创建关系；已有 v1/v2 JSON
仍返回原字节和摘要。封存 Case 不能重开；“从封存 Finding 续办”原子建立新的开放 Finding，保留
旧 revision/digest 和续办理由，新记录的复核、进度及责任均从未记录开始。
`investigation_reader` 可回读这些材料和包，页面不提供写入动作。

## 调查队列与个人筛选

“调查队列”按当前部署内实际可读的完整 Finding 集合统计和分页。当前跟进、期间新建、依据变化分别呈现；封存不会自动结束跟进，旧分类和 Case 状态也不等于复核结论。可筛选责任人、期限、进度、结论、依据状态及 Case 状态。期间按创建时间计算，自定义区间使用带时区的起点和不包含的终点。

“加载更多”沿用同一读取时间与集合版本；相关记录变化后须刷新，避免把不同版本的页拼在一起。从队列进入指定 Finding 后可返回原筛选。原 Case 列表的最近 50 条限制不用于队列统计。

个人筛选可保存、更新和删除；只读调查者也可以管理自己的筛选，但不会获得 Case 写权限。网络结果未知时保留原命令并原样重试；取得历史回执后仍会重新读取当前筛选，避免让旧回执覆盖后续修改。保存的筛选不扩大读取权限。

并发修改导致版本冲突后，点击“重读保存列表”。页面保留未保存草稿并展示新的保存版本；选择“载入已保存版本”会替换草稿，选择“保留草稿继续修改”会在保留草稿的同时采用新版本，核对后可再次更新或删除。选择前不能重复提交旧版本。如果该保存项已被别人删除，草稿仍保留，可另存为新项。读取期间更换选择或继续编辑时，迟到响应不会覆盖当前编辑。

队列目前使用部署角色权限；跨项目 ACL、完整安全线索来源和真实外部效果验证仍未交付。

## 本地合成 PostgreSQL 测试

在普通本地进程中设置 `XINSIGHT_RESPONSIBILITY_LOCAL_TEST=1` 并提供 DSN 时，六个相关测试包会在运行任何测试前要求 `XINSIGHT_LOCAL_TEST_DATABASE_SCOPE` 指向独立记录的目标 JSON，字段为 `host`、`port`、`database`、`user`、`database_oid`、`system_id`。目标应先按该次授权明确新建库，再只读记录其身份，不能从待测 DSN 自动接受目标。维护库不允许成为目标；连接解析结果及实际数据库 OID、集群身份必须一致。外部传入的 hostctl 恢复 DSN 会被拒绝，原生资格测试须从受保护的建库入口派生。

本包目标及可重现验证见 `output/xi-c-queue/local-database-scope.json` 与 `target-guard-verification.py`。无 DSN 的离线测试不连接数据库；现有 GitHub Actions 临时服务继续使用其既有独立建库和角色合同，未改变 CI 配置。该防护不替代数据库或外部操作授权。
