# 从 UniRouter 到 X-Insight 的首条执行记录

[English guide](getting-started.md#find-the-same-request-in-x-insight) · 对应 FPV27 签名预览版（schema 49）

先按 [FPV27 中文下载与验签速查](releases/v0.2.0-dev.fpv27.md#中文速查)和[安装、首个账号与连接指南](getting-started.md)准备两端。账号持有人在各自已批准的 HTTPS 入口登录。已有有效连接时沿用同一来源和项目。[发布状态与随包手册双语勘误](release-readiness.md)说明当前版本及已验范围。

## 用同一请求查找并对账

1. 从 [UniRouter 的请求记录](https://github.com/foigent/unirouter/blob/main/docs/community/getting-started.md#make-and-inspect-a-request)选一条获准、非敏感、已完成的请求，记录连接来源、组织／项目、网关 **Request ID**、完成时间与时区，以及已记录的结果、输入／输出 Token、客户实收金额及币种。两端使用同一个 Request ID。执行和客户账务事实以 UR 为准，尚未结算时先在 UR 确认终值。
2. 在 XI 的常规 HTTPS `/login` 用已获该项目阅读授权的 owner 登录，再用独立会话以普通 reader 登录。reader 需要准确来源和项目的元数据授权。两种角色均从**运行与执行 → 执行记录**进入，以精确匹配输入 **Request ID**；有来源筛选时选相同来源，按浏览器本地时区填写起止时间，确保覆盖该请求。打开结果后核对来源、组织／项目和 Request ID，再比较各自可见证据里的结果、Token 和金额。可见字段取决于当前授权；连接管理或元数据读取权限均不授予正文阅读。
3. 对账时使用相同口径、币种与单位。客户实收、供应侧费用观察、估算各有含义。若标注为微元（micro-CNY），除以 1,000,000 才是 CNY。区分明确记录的零、未结算及证据不可用。请使用自己获准查阅的真实请求及数值。

搜索的起止时间决定查哪些执行；读取截止时间 `as_of` 限定能读到的证据时间。比较已保存的详情时，保留原链接返回的截止时间和 `evidence_revision`（如有）。证据修订固定该次读取所用的已提交证据。仅带读取截止时，晚到但发生在该截止时间内的证据仍可能出现。从**费用与使用**打开调查时，入口保留所选执行、事件和读取截止。重开已保存读取仍按当前授权；若读取过期或授权已变，核对权限后按允许范围建立新读取。

## 什么时候可见，没找到怎么查

已有连接先按准确的 Request ID 查找。已收到时直接对账。**自动同步**已开启时沿用现有设置，同步进程在获准范围内轮询，配置间隔是最短间隔。事实已在 XI 提交且当前读取和角色获准时，才可在执行记录中找到。连接检查、数据提交和来源游标确认可以发生在不同时间。

没有记录时，先核对 UR 是否允许导出、来源及项目、请求 ID 和时间范围。如果事实尚未到达，且连接是默认手动的新连接或原本就在手动模式的已有连接，由有权的操作者核实当前采集范围后，在这个连接上选**同步一次**。该操作有运行上限，也可能接收范围内的其他合规记录。

获准的操作者可在**连接器**点**刷新本地状态**，查看最近出站检查、最近数据提交和同步结果。刷新只读取状态。区分空结果、部分完成和错误，有安全诊断代码就记录该代码。若提交同步后响应丢失，先在产品里确认先前请求。若 owner 能找到而 reader 找不到，核对 reader 当前的来源、项目与元数据授权。不要分享连接密钥或客户正文。详见[随版中文连接同步手册](https://github.com/foigent/x-insight/blob/4d2f53b048f63439fff59f6194946953732ea106/docs/manual/zh-CN/connection-sync.md)、[账号与项目阅读](https://github.com/foigent/x-insight/blob/4d2f53b048f63439fff59f6194946953732ea106/docs/manual/zh-CN/accounts.md)和[数据处理边界](data-handling.md)。
