# X-Insight 0.2.0-dev.fpv25 installation and verification

X-Insight is an Apache-2.0 development preview for supported Ubuntu 22.04/24.04 amd64 systemd hosts. FPV25 shows where an execution-facts feed failed and gives safe, actionable guidance. Existing project and body grants continue to apply. It keeps database schema 47 and uses the existing installation, backup and upgrade commands.

## Authenticate the release

Use the [canonical release](https://github.com/foigent/x-insight/releases/tag/v0.2.0-dev.fpv25) and the immutable authority-document commit linked in its publication record. Read `docs/community/release-authority.json` at that commit. Authenticate the owner and match the public trust store, key fingerprint and every downloaded byte to the pinned record before executing the Linux verifier. The authority commit and product source commit have distinct purposes. The signed manifest's creation time follows the product source commit timestamp.

## Choose one download route

- **Full bundle** for a new installation or an explicitly approved full transfer. Follow the full download step, then verify the signed archive.
- **Delta** for an authorized upgrade with the exact signed FPV24 archive cached, including the original-host upgrade planned for this release. Skip the full download step. Reconstruct the archive locally, then verify it with the same ordinary command.

## Full bundle downloads

Download the full archive, standalone Linux verifier and public trust store. Authenticate their hashes against the pinned authority. The optional `SHA256SUMS` attachment also lists these hashes. Run `sha256sum -c SHA256SUMS` if all listed files are present.

## Delta downloads and reconstruction

Keep the exact signed FPV24 archive `xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz` with digest `sha256:34aa6dd9e9ecff09015fe45c34d22e204bc6ca43c223413f6329bfba9c4aa92c`. Download `payload.zst`, `delta.json`, `release-manifest.json` and `release-manifest.sig`. Obtain the trust store if it is absent. Authenticate every input against the pinned authority.

### Prepare the verifier only if needed

If the exact FPV25 verifier is cached and its raw hash matches the pinned authority, go straight to materialization. If a same-name file has a different hash, stop and use a fresh staging directory. Do not execute or overwrite it.

If the verifier is absent, download `xinsight-release-linux-amd64.gz` and run this block in staging. It checks both hashes and refuses to overwrite an existing file.

```sh
printf '%s  %s\n' 'e4f8da8b6a68f5668eca9b88289560b990e69068cd34af175b26e8c37eed9dbc' 'xinsight-release-linux-amd64.gz' |
  sha256sum --check - &&
  (set -C; gzip -dc ./xinsight-release-linux-amd64.gz > ./xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3) &&
  printf '%s  %s\n' '7f6e2a726d6f8535b7d848dfebf3442ad24fbea6e38681efdbf2300a6791647f' 'xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3' |
  sha256sum --check - &&
  chmod 0755 ./xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3
```

### Materialize the signed archive

```sh
./xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3 materialize-delta \
  --plan ./delta.json \
  --plan-sha256 sha256:47de3ceb76ae49114dac5c36398825a9f56e12102b4e8bea15d1b066776f60bf \
  --basis /approved/cached/xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz \
  --patch ./payload.zst --manifest ./release-manifest.json \
  --signature ./release-manifest.sig --trust-store ./trusted-release-keys.json \
  --output /approved/staging/xinsight-v0.2.0-dev.fpv25-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3.tar.gz
```

Use a new absolute output path in private staging. For a read-only rehearsal, replace `--output PATH` with `--check`. An incorrect basis, changed delta or failed verification stops this route. Full transfer is a separate operator choice where authorized.

## Verify the downloaded or reconstructed archive

Set `archive` to the actual absolute path of the signed archive. This example uses the delta output path. Execute the verifier after its raw hash and the public trust match the pinned authority.

```sh
archive=/approved/staging/xinsight-v0.2.0-dev.fpv25-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3.tar.gz
chmod 0755 ./xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3
./xinsight-release-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3 verify \
  --artifact "$archive" \
  --trust-store ./trusted-release-keys.json \
  --expected-commit b77fa1d7cff40a9adafe495d1c4951632819a4d3 --expected-version 0.2.0-dev.fpv25
```

## Install or upgrade

Run the verifier's `extract` with the same archive, trust, expected commit and version plus `--destination /approved/new-fpv25-staging`. Use a new absolute staging directory. Follow the packaged manual for the supported host, systemd, dedicated PostgreSQL 16, roles, TLS and trust. A new installation uses the native first-owner activation flow.

On an existing installation, preserve the current installation, database, configuration and trust identities. Make a native private backup, check it and complete the supported isolated restore before the authorized maintenance operation. Then run the staged target controller.

```sh
sudo /approved/new-fpv25-staging/bin/xinsightctl upgrade --check \
  --artifact /approved/staging/xinsight-v0.2.0-dev.fpv25-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3.tar.gz
sudo /approved/new-fpv25-staging/bin/xinsightctl upgrade \
  --artifact /approved/staging/xinsight-v0.2.0-dev.fpv25-linux-amd64-b77fa1d7cff40a9adafe495d1c4951632819a4d3.tar.gz
sudo /opt/x-insight/current/bin/xinsightctl status
```

Verify normal owner and reader sessions, explicit project access and the foreign-project and body-access boundaries. Use the established two-administrator controls for an existing UniRouter connection. Acceptance of automatic rotation requires evidence from that installed connection.
