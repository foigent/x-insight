# X-Insight 0.2.0-dev.fpv21 (release candidate)

FPV21 adds durable local accounts, holder activation and recovery, targeted session invalidation, and an owner editor for explicit project metadata grants. Owner administration and granted reading can compose; body access remains separately authorized. The native private backup/restore contract includes account state. Schema47 cannot run with the schema46-only predecessor binary; recovery requires the verified paired private backup and supported Restore/Resume route.

This is a development preview under Apache-2.0. Third-party notices and licenses remain in the signed payload. It is not a stable or Production qualification.

## Install or preserve an existing installation

Use a qualified Ubuntu amd64/systemd host with a dedicated PostgreSQL 16 database and the documented protected configuration, four database roles, accounts and public trust. Follow the packaged English-first manual. For a new empty-database installation use the staged controller's `install --check`, then its normal `install` only after the preconditions and target scope are satisfied.

For an existing supported predecessor, preserve the installation identity, configuration, roles, trust, body-custody keys and full private backup. Verify the supported isolated restore before the maintenance window. Use the candidate controller, which understands schema47:

```sh
sudo /approved/new-fpv21-staging/bin/xinsightctl upgrade --check --artifact /absolute/path/to/xinsight-v0.2.0-dev.fpv21-linux-amd64-6463d980958fae86d975eecde239b9534ec831a5.tar.gz
sudo /approved/new-fpv21-staging/bin/xinsightctl upgrade --artifact /absolute/path/to/xinsight-v0.2.0-dev.fpv21-linux-amd64-6463d980958fae86d975eecde239b9534ec831a5.tar.gz
sudo /opt/x-insight/current/bin/xinsightctl status
```

These are instructions, not proof of a completed installation. Do not hot-swap the old binary, downgrade schema47 in place, reset an owner password to work around migration, or replace an immutable package after a failure. Preserve exact failed identities and use the native journal/backup recovery contract.

After activation, confirm account identities and existing grants, then use normal HTTPS login. Owner reading requires an explicit source/project grant. Holder recovery is completed on the dedicated page; passwords and recovery links must stay out of logs, releases and ordinary evidence. Verify owner and ordinary-reader scope separately; preserve denial for foreign projects and bodies.
