# X-Insight 0.2.0-dev.fpv24 installation and verification

X-Insight is an Apache-2.0 development preview for supported Ubuntu 22.04/24.04 amd64 systemd hosts. FPV24 resolves a project number such as `2` to the exact Runtime reference `project-2` for the selected source. Overview and cost filters accept source project references, and reading and body grants continue to apply. It keeps database schema 47 and uses the existing installation, backup and upgrade commands.

## Authenticate the release

Use the [canonical release](https://github.com/foigent/x-insight/releases/tag/v0.2.0-dev.fpv24) and the immutable authority-document commit linked in its publication record. Read `docs/community/release-authority.json` at that commit. Authenticate the owner and match the public trust store, key fingerprint and every downloaded byte to the pinned record before executing the Linux verifier. The authority commit and product source commit have distinct purposes. The signed manifest's creation time follows the product source commit timestamp.

- Config `xinsight.config.v1`, schema 47, manual `0.2.0-dev.fpv24/manual-r1`.

## Choose one download route

- **Full bundle** for a new installation or an explicitly approved full transfer. Follow the full download step, then verify the signed archive.
- **Delta** for an authorized upgrade with the exact signed FPV23 archive cached, including the original-host upgrade planned for this release. Skip the full download step. Reconstruct the archive locally, then verify it with the same ordinary command.

## Full bundle downloads

Download the full archive, standalone Linux verifier and public trust store. Authenticate their hashes against the pinned authority. The optional `SHA256SUMS` attachment also lists these hashes. Run `sha256sum -c SHA256SUMS` if all listed files are present.

## Delta downloads and reconstruction

Keep the exact signed FPV23 archive `xinsight-v0.2.0-dev.fpv23-linux-amd64-82ca877d023058e48c93975c50171f606f8924f2.tar.gz` with digest `sha256:4497590a188a6abb90f7e90c1b71d279b7aff4fdde2ec458b48795a19c4feb2d`. Download `payload.zst`, `delta.json`, `release-manifest.json` and `release-manifest.sig`. Obtain the trust store if it is absent. Authenticate every input against the pinned authority.

### Prepare the verifier only if needed

If the exact FPV24 verifier is cached and its raw hash matches the pinned authority, go straight to materialization. If a same-name file has a different hash, stop and use a fresh staging directory. Do not execute or overwrite it.

If the verifier is absent, download `xinsight-release-linux-amd64.gz` and run this block in staging. It checks both hashes and refuses to overwrite an existing file.

```sh
printf '%s  %s\n' 'de1c0419042d63adeae1f45ab97dca3977c9e35de4d1fba03eade85bfe763619' 'xinsight-release-linux-amd64.gz' |
  sha256sum --check - &&
  (set -C; gzip -dc ./xinsight-release-linux-amd64.gz > ./xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93) &&
  printf '%s  %s\n' 'c2762fd67747e743249cc59ba38727aceefc3b8d7493b3dbb4140494d75349ff' 'xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93' |
  sha256sum --check - &&
  chmod 0755 ./xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93
```

### Materialize the signed archive

```sh
./xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93 materialize-delta \
  --plan ./delta.json \
  --plan-sha256 sha256:b5d53fe37beb1792c5e91fedb0e1ba2e7894bd43240faa57393a2261d7986e77 \
  --basis /approved/cached/xinsight-v0.2.0-dev.fpv23-linux-amd64-82ca877d023058e48c93975c50171f606f8924f2.tar.gz \
  --patch ./payload.zst --manifest ./release-manifest.json \
  --signature ./release-manifest.sig --trust-store ./trusted-release-keys.json \
  --output /approved/staging/xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz
```

Use a new absolute output path in private staging. For a read-only rehearsal, replace `--output PATH` with `--check`. An incorrect basis, changed delta or failed verification stops this route. Full transfer is a separate operator choice where authorized.

## Verify the downloaded or reconstructed archive

Set `archive` to the actual absolute path of the signed archive. This example uses the delta output path. Execute the verifier after its raw hash and the public trust match the pinned authority.

```sh
archive=/approved/staging/xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz
chmod 0755 ./xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93
./xinsight-release-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93 verify \
  --artifact "$archive" \
  --trust-store ./trusted-release-keys.json \
  --expected-commit fa1e64e1d1259c3b7d631baa7794952b0ae72d93 --expected-version 0.2.0-dev.fpv24
```

## Install or upgrade

Run the verifier's `extract` with the same archive, trust, expected commit and version plus `--destination /approved/new-fpv24-staging`. Use a new absolute staging directory. Follow the packaged manual for the supported host, systemd, dedicated PostgreSQL 16, roles, TLS and trust. A new installation uses the native first-owner activation flow.

On an existing installation, preserve the current installation, database, configuration and trust identities. Make a native private backup, check it and complete the supported isolated restore before the authorized maintenance operation. Then run the staged target controller.

```sh
sudo /approved/new-fpv24-staging/bin/xinsightctl upgrade --check \
  --artifact /approved/staging/xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz
sudo /approved/new-fpv24-staging/bin/xinsightctl upgrade \
  --artifact /approved/staging/xinsight-v0.2.0-dev.fpv24-linux-amd64-fa1e64e1d1259c3b7d631baa7794952b0ae72d93.tar.gz
sudo /opt/x-insight/current/bin/xinsightctl status
```

Verify normal owner and reader sessions, explicit project access and the foreign-project and body-access boundaries. Use the established two-administrator controls for an existing UniRouter connection. Acceptance of automatic rotation requires evidence from that installed connection.
