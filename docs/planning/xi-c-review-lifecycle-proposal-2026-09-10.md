## 3. 产品与数据合同

**结论。** 无扩展明确“未记录”。新复核支持待复核、证据支持、证据不支持、证据不足，保存判断文本/版本、作者、服务端时间、原因和依据快照。支持结论须有支持引用；不支持须有反证；证据不足可引用 gap 或明确写出缺什么，不强迫制造来源记录。人工结论标明是谁基于什么作出，不更改源事实或旧 Finding 分类。

**首次组合开始复核（review20 补充）。** 纳入原 P2-M03，本包复用封存续办所需的事务内创建能力：选择已有开放 Case（带 expected_case_version）或提供新 Case 的有限字段，提交明确 Finding 判断、所选可读 Evidence/Gap 引用、初始复核结论/理由和 operation_id；服务端一个事务完成 Case（如需）、Finding、引用关联、依据快照、初始复核/明确未开始进度、追加动作与创建回执。可以从“待复核”开始，不因创建即确认问题，责任默认未记录；若首次即给出实质结论，执行同样的支持/反证/缺证校验。

创建幂等身份绑定当前部署、human actor、创建操作类型和 operation_id，不依赖尚未生成的 Finding ID。相同内容重试返回原 Case/Finding ID 和回执；异内容冲突；并发同动作只创建一套。先当前鉴权、后查原回执，新动作才检查最新依据和版本；任何引用/写入/提交失败都不留下孤立 Case、Finding、引用或初始状态。前端使用一个正式命令，不串行调用旧创建接口来拼成功。旧 CreateCase/CreateFinding 单独入口继续原合同，只提取实际共用的事务内创建函数。

**进度。** 未记录与明确“未开始”分开；允许未开始→跟进中/已结束、跟进中→已结束、已结束→跟进中。结束和重开都必须有原因，结论不随进度自动改变。只有未结束的已记录进度才参与“跟进期限已过”；只有责任记录而尚无进度时继续说明进度未记录，不补推历史状态。

**依据与重评。** 快照同时记录复核时已知的 Finding 引用集合，以及本次结论实际选用的 EvidenceLink/GapLink、关系、不可变事件 hash/source_ref、GapResolution 版本和判断版本；不能把本来已知但未采用的引用当作后来新证据。Case 级引用只有被明确选择才属于该判断。后续相关 Finding 引用增加、所选 gap 版本变化时，重新计算当前依据，与上次复核快照比较并提示待重评。新的 `record_review` 可显式调整支持/反证选择并记录新快照，不删除原 EvidenceLink 以伪装撤回，也不声称已实现独立的外部关系撤回协议。新证据不自动覆盖结论、结束记录或重开进度；同一引用重放、无关 Case/Finding/图版本变化不触发。

**Gap 当时内容（review20 补充）。** 每个实际采用的 gap 依据保存类型化快照：gap_id、GapLink 的 affected_claim/gap_type/关系快照，以及解决记录是否存在、resolution_version、state、note、updated_by_subject、updated_at。无解决记录显式 recorded=false/version=0，不补造 open 状态或作者。版本和内容必须从同一个数据库可见行版本读取，连同依据 schema 版本与规范化摘要持久化；不是拿旧版本标签配后来 note。只保存复核实际采用的有限字段，沿现有字段长度限制及明确的引用条数上限拒绝超界，不保存 raw 来源载荷或新增通用 Gap 历史系统。

该内容快照进入同次不可改的复核/结束动作依据，后续历史读取使用已存快照，pack v3 携带实际内容，备份恢复核对快照、摘要与动作链；不通过 JOIN 当前 capture_gap_resolutions 重建历史，也不要求历史版本等于当前版本。当前 gap 状态可单独展示并标为“当前”，发生变化后提示重评；旧复核/结束/封存始终保留当时采用内容，当前可读性限制另行说明。选择界面使用同一服务端依据解析器提供可见内容预览，提交带该预览的依据摘要/预期版本，事务内重新核对；预览只读，不预创建 Case/Finding 或占位记录。

提示在正式读取时求得，说明 evaluated_at；本包不承诺后台主动通知。引用不可获得与真正无变化分开，不能因为 hash 尚在就显示内容仍可读取。外部源修订/撤回尚无合格正式合同的部分明确待源，本包不新增伪造的来源协议；本地可验证路径是已接纳 M0 引用、GapResolution 与人工选择的显式版本变化。

**封存续办。** 开放 Case 内允许结束后重开；sealed Case 始终不解封。续办命令在一个事务中创建新的 Finding（选择现有开放 Case 或新建 Case）及指向旧 Case/Finding/封存 revision/digest 的关系，保留操作者、原因和幂等回执。新记录从未复核/未登记责任开始，旧结论只作为历史引用，不自动复制成当前判断或授予负责人权限。
