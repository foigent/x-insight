## 1. 推荐交付及独立性

推荐下一项是：**有权人员在已有开放 Case 的 Finding 上登记或修改本地负责人、可选期限及修改依据；刷新后看到保存结果和完整追加历史；并发、重试、失败和封存均不会造成覆盖或半写。** 旧记录明确显示“责任信息未记录”，不会默认把创建者设为负责人。

这是可单独完成的一段用户工作。它只需要 XI 已有 Case/Finding、本地账号、人工会话和同一逻辑数据库，不消费费用 reading，不等待 A0 的 20 次性能结果，也不需要 UR 新 profile、真实安全事件或资源控制权。负责人登记属于人工记录，不认定安全事实，不授予被指派者访问权。

本片不包含复核结论、跟进结束/重开、线索产生、当前事项队列或新证据重评；这些仍是 XI-C 必须完成的后续部分，而不是被删掉的目标。不能把本片交付表述为 SE-03、P2-M03、XI-C 或父级完整工作通过。

## 3. 数据与用户语义

建议新增两张小表，表名及迁移编号在实施时按届时主线核对；当前 schema 25 不变。不新建数据库、消息服务或通用事件框架。

| 对象 | 有限字段与约束 |
| --- | --- |
| `case_finding_followups` 当前责任投影 | `(case_id, finding_id)` 唯一，并以组合 FK 指向原 Finding；可空 `assignee_subject_id`、写入时显示名快照、成对可空 `due_at` / `due_timezone`；`version`、`updated_at`、`updated_by_subject`、最后动作引用。无行表示未记录，首个明确登记为 version 1，即使负责人和期限均为空 |
| `case_finding_actions` 追加动作记录 | Case/Finding、服务端 actor/time、operation_id、规范化请求摘要、expected_version、expected_case_version、旧/新类型化责任值、原因、结果版本与原始回执。唯一 `(case_id, finding_id, actor_subject_id, operation_id)`，同一 Finding 的结果版本唯一；写入后不给 workspace UPDATE/DELETE 权限 |

每次动作只接受这组字段，不接受任意 JSON 扩展。原因必填且有界（建议沿用备注的 4000 UTF-8 字节上限），说明本次责任决定；它不是“风险已证实/已修复”的证据。记录明确绑定 Finding 及动作发生前的 Case.version。涉及来源依据的复核将来使用自己的版本化 basis，不从此原因文本补造。

负责人可明确未分配；候选为已存在、启用的本地账号，可以没有该 Case 的读取权。保存不发通知、不赋权。新分配到失效/未知账号拒绝；原负责人之后失效或移除时保留 subject 与当时显示名，当前页面提示失效/无法确认并允许重新分配，不自动换人。只修改期限时允许保留已失效的原负责人并提示，不强迫篡改历史责任。

期限同时保存绝对时间（UTC）及 IANA 时区。客户端提交带偏移的 RFC3339 时间和时区，服务端验证该时刻/偏移与时区相符；不存在或重复的当地时间须在 UI 明确校正或选择偏移。清空时两字段同时为 null，不用日期字符串/浏览器默认时区猜到期点。

未设期限不算逾期；开放记录可显示“登记期限已过”，并给出 evaluated_at 和时区。因本片尚无跟进终态，不能由此推导事项未结束、违反 SLA 或风险持续存在。封存页面/包说明的是封存时责任记录，不把后来账号状态或当前时间写回旧快照。

## 4. 有限 API 与原子提交

沿用第 19 份候选 `/review` 与 `/review-actions`，此片只开放 update_followup 的责任/期限字段。明确不支持的复核/结束动作返回错误，不提供占位成功。正式 OpenAPI 同步声明实际支持的子集。

| 候选入口 | 本片输入/输出 |
| --- | --- |
| `GET /api/v1/cases/{case_id}/findings/{finding_id}/review` | 责任 `recorded`、扩展 version、case_version、负责人快照和当前可核状态、期限、允许动作、历史第一页。未实现的复核结论不伪装为已记录 |
| `POST /api/v1/cases/{case_id}/findings/{finding_id}/review-actions` | `operation=update_followup`、operation_id、expected_version（未记录为 0）、expected_case_version，以及完整责任/期限值和 reason；成功返回该动作持久化的回执、结果版本和 Case.version |
| `GET …/review/history?through_version=…&before_version=…&limit=…` | 有界 limit、最后动作版本与固定历史上界；初次 review 读取在短只读事务中取一致的当前投影/Case.version/历史上界。后续只读该上界内追加记录，每页重新鉴权；可查全，不只显示最近若干条却声称完整 |
| `GET /api/v1/security/assignee-candidates?case_id=…&finding_id=…` | 显式验证 Case/Finding 和人工调查写权限，再返回本次已加载本地账号中的稳定引用、显示名和状态。利用当前 MaxAccounts=100 返回完整有界集合与 total/complete，不引入目录同步或分页缓存；不直接序列化账号配置 |

请求中不接受有效 actor/time/role。负责人接口在 `/security` 下，不能误以为 `/cases` 的现有中间件已经覆盖它；处理器必须显式执行同等鉴权。Agent token、无调查权限会话、跨 Case 的 Finding ID、撤销/过期会话、无/错 CSRF、跨源、未知/重复字段均不得保存或泄露历史。

建议事务顺序：

1. API 先校验当前会话、对象读取/动作权限、同源/CSRF及有限输入；账号目录只产生无秘密的查找结果，不在 HTTP 请求中重新打开凭据文件。
2. 事务按 Case 行 → Finding/责任投影顺序取锁，并确认 Finding 属于该 Case。先取锁而不要求 open，以允许已成功动作在后来封存后安全重放回执。
3. 查同对象、同 actor、同 operation_id。规范化内容相同则返回已持久化原回执，不递增任何版本；内容不同返回冲突。此检查在新动作的版本、开放状态和新负责人有效性检查之前；仍须完成步骤 1 的当前鉴权。
4. 对新动作验证 Case open、expected_case_version 和责任 expected_version；才验证新分配账号、期限与原因。Case.version 也参与比较，使依据/其他调查内容已改变时要求重新阅读。Finding.version 保持原字段语义，不挪作责任版本。
5. 写当前投影、完整追加记录/回执，递增责任和 Case.version，并原子提交。任一写入、提交或取消失败均回滚；没有独立“保存历史”请求，也没有队列最终补写。

Case 行锁足以串行同 Case 的新动作并使幂等记录一次插入完成；借鉴已有 saved-filter 的摘要/回执规则，但不复用其业务表或改动 A0 文件。重复同动作即使后来有人再次修改，仍返回原版本回执；UI 随后 GET 当前投影，不能把历史回执覆盖到最新页面。

封存入口在读取扩展/历史前取得同一 Case 锁，保留 serializable/版本条件；既有 touchOpenCase 写入遵守相同父行串行边界。并发结果须是“动作先提交且全部进入包”或“封存先提交，新动作被拒绝”；不能成功封存半份责任记录。序列化冲突映射为可解释的冲突，客户端重新阅读，不增加隐藏重试。

历史翻页采用上表的有限版本参数：服务端先验证路径对象和当前主体权限，再校验版本为合法整数、历史上界不超过当前版本、翻页位置位于该上界内，SQL 始终限定本 Case/Finding。UI 沿首次读取的 through_version 翻页，新动作留待刷新；版本参数不是权限凭据。现有 `internal/pagination/cursor.go` 仅支持执行相关 kind，且是编码/绑定校验，**不是签名游标**；本片不扩展它，也不为追加历史建立快照服务。这是对第 19 份候选游标设计的局部简化，完整安全队列的范围/版本游标要求保留。

## 5. 页面与兼容

新的封存包建议使用 `xinsight.evidence-pack.v2`，包含责任投影、当时显示名、全部有序动作/回执及版本；不包含当前账号凭据或即时可用性。JSON 摘要仍覆盖实际下载的精确字节，HTML 按 schema_version 显式选择读取逻辑，未知版本拒绝静默解释。v1 包保留原字节/摘要与原 HTML 表达；新 Case 封存使用 v2，升级前开放记录中没有责任扩展时明确未记录，不反填历史。

迁移采用当前 schema 25 之后的新增迁移，既有 1—25 迁移字节不改。角色表名单、当前 schema contract/生成输入、升级与备份恢复合同同步修改；历史 rc.10 权限常量、schema 23 正式身份、schema 24/25 前态与旧 pack 路径继续保留。新投影可按约束更新；历史表 workspace 只可 SELECT/INSERT，importer/Agent 不新增写权。恢复要验证历史不可改、版本/回执唯一性及包摘要，不只检查能启动。

不支持通过 down 迁移删除已有责任历史来回退；失败前保留原备份，回退采用正式支持的恢复路径。新 v2 不能承诺旧客户端理解；OpenAPI/兼容说明分别列出旧 v1 读取与新 v2 支持，未知版本行为有负向验证。封存后本片禁用新责任动作，继续跟进的新开放记录关系仍由 XI-C 后续交付，不解除封存。
