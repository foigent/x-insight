## 拟实施范围与行为

### 1. 趋势：全期间概览与小时详情都可用

推荐复用已支持的 series `bucket_seconds` 参数，不新增后端聚合路径或图表依赖。默认概览按24小时→1小时、3天→3小时、7天→6小时、30天→24小时，最多30桶；页面明确标注粒度。这里的24小时桶以reading期间起点对齐，不冒称自然日，时间标签及悬浮/键盘说明使用reading.display_timezone并展示完整起止边界。

保留“每小时”粒度选项：24小时模式仍直接展示；7/30天的小时详情在图表内部有界横向滚动，桶有可读最小宽度，滚动条和提示可见，页面本身不溢出。不通过隐藏溢出、丢掉桶、采样漏钱、减少可选期间或取前N桶修复。默认概览展示全期间，每小时详情保留原粒度能力。

粒度切换沿用同一个reading_id、cutoff、金额口径与成员，不创建新reading；最后不足整桶的终点仍等于period.end_exclusive。BigInt金额、零桶“不代表完整”和known subtotal语义保持。零值应显示零/基线，不画成正金额；轴标签稀疏显示，精确桶值仍可访问。趋势请求也采用下述成功状态提交规则。

文件：WorkbenchPage、已有series客户端参数、局部样式及相应测试；服务端API/SQL/schema不改。粒度是本计划明确提出的产品呈现选择，待双方确认后实施。

### 2. 覆盖：固定reading依据与当前来源观察分开

在趋势附近展示本reading的覆盖依据：期间完整性未知、成员投影是否完成、可用的采集起点、历史缺口和profile缺口解释。用稳定的code→用户文案映射，未知code显示“存在尚未解释的覆盖限制”，不由未知值推断complete。

- `period_precedes_capture_start`：说明至少一个已授权来源的采集起点晚于所选期间起点，该部分历史未确认覆盖；不能称为已经补齐或全部费用为零。
- 单来源可标注该来源已知采集起点；多来源聚合的capture是最早已知起点，不能把它当作所有来源共同覆盖起点，不能从一个min时间编造所有来源的缺口区间。
- `source_profile_capture_gaps_present`与历史未覆盖分别解释；`source_not_currently_connected`/not_connected/observed属于观察状态，均不蕴含期间完整。
- opaque received_watermark仅表示消费位置已记录/未知，可在说明中解释其不证明时间完整；不把它解析成时间。summary.last_received_at是本reading成员中最近入库时间，projection_watermark是这些成员的投影时间，均不改称整源最新同步。
- `scope_limited_unknown`明确“当前授权不足以判断整源覆盖”，不显示整源采集起点/水位/缺口计数；即使后端意外附带整源字段，受限UI也不展示。仍允许展示按授权成员得出的已知小计和投影信息。
- Reading固定coverage与sources端点的当前观察有明确标签；后者变化不改写旧reading覆盖。无coverage权限的可选来源面板403按能力缺失降级，不能借此暗示金额完整。

只消费已有字段，不扩展授权/整源查询，不新增历史回填或期间完整性推定。

### 3. 请求失败：视图控制与数据共同成功，再提交显示

只在工作台内收拢重复的请求完成/失效处理，不建立全应用状态框架。用已显示成功的维度、模式、粒度与对应数据组成一致视图；请求期间有loading并约束互相冲突的交互，成功且reading/request generation仍匹配时才一起提交。保留旧成功视图时，选择器仍显示其真实标签；不提前把目标标签套到旧数据。

| 失败/事件 | 拟定显示与恢复 |
| --- | --- |
| 410过期、409 workbench_access_changed、reading主链401/403/404 | 清除该reading及summary/series/contributions/details/source状态，取消或使全部旧请求失效；不再显示旧金额/依据。展示明确原因与“按当前权限重新建立阅读”入口。401沿用全局退出；403不自动扩大scope重试 |
| 普通网络/5xx/429失败 | 保留最后一次成功的同一视图及其标签，标明更新失败，提供显式重试；未成功的维度/模式/粒度不生效。429遵守已有错误/重试提示，不加自动重试循环 |
| 明细打开/明细翻页/贡献翻页失败 | 同样分类；失效错误清除整个旧reading。普通失败保留合法的原页和光标，不重复追加、不改总分母；详情分支也能看到错误并返回 |
| sources/saved可选功能失败 | 普通403能力缺失只影响该功能；sources返回reading过期/授权变化则不能被allSettled吞成普通“来源不可用”。保存操作自己的冲突不误清理合法reading |
| 快速切换/切换期间后的旧响应 | 同一reading generation加请求序号约束；可用现有AbortSignal停止过时请求，过时成功和失败都不能覆盖新视图或解除新请求busy |

保存仍采用appliedConfig，范围草稿不会被当作已显示范围。错误恢复重新建reading是明确用户动作，不在后台悄悄换cutoff。
