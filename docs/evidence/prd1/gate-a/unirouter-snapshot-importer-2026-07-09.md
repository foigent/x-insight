## Scope

This note covers the first X-Insight-side UniRouter snapshot import checkpoint:

- `xinsight-importer unirouter import-snapshot`;
- typed UniRouter PRD5 snapshot parsing;
- mapping `request_trace_events` into M0 evidence events;
- mapping `call_logs` into M0 usage evidence events;
- mapping top-level snapshot `capture_gaps` into `gap.capture.detected` evidence events;
- refusing snapshots with raw prompt/response/API-key safety flags or unsafe-looking keys;
- second-pass in-memory import to prove `duplicate_noop` behavior.

This does not prove database persistence or read APIs by itself. Persistent import is tracked in `unirouter-persistent-snapshot-import-2026-07-09.md`.

## Important Implementation Judgment

`ingested_at` is excluded from canonical event hashing.

Reason: imported evidence idempotency must be based on source identity and event semantics, not the local time at which the importer happened to run. Otherwise a legitimate re-import of the same snapshot would become an idempotency conflict.

## Current Boundary

The importer intentionally remains local and in-memory.

It does not:

- write to Postgres `evidence_events`;
- write to Postgres `capture_gaps`;
- maintain persistent adapter cursor state;
- expose imported events through APIs;
- infer missing trace rows;
- store raw prompt/response content.
